COURSE 4: JÖRMUNGANDR

    Course 5 · Lesson 1

    The Game Page

    Play Jörmungandr for a few minutes first. You are the world serpent of Norse myth: steer round a grid, eat to grow, don't bite your own tail, and catch Thor to cross into the next of the nine realms. It's the classic game of Snake, with a few twists.

    Tic-tac-toe was built out of HTML buttons. Jörmungandr is different: almost everything you see is painted onto a single <canvas>, sixty times a second. So the page itself is small:

    Things to notice

    • width="960" height="540" set the canvas's drawing size: 960 by 540 pixels to paint on, a 16:9 shape like a TV. CSS can then shrink or stretch the canvas on screen, and the drawing scales with it. The game always thinks in those 960 by 540 pixels, whatever the window size.
    • The aria-label matters more than usual. A screen reader can't see anything painted on a canvas, so the label is the only description it has.
    • #load-error starts empty. If the art or the questions fail to load, the game writes the error there rather than leaving a blank board.
    • One script, js/jormungandr/game.js, is a module that imports the rest. The game is split into eleven small files under js/jormungandr/: board.js, snake.js, input.js, play.js, items.js, thor.js, render.js, body.js, art.js, hud.js and game.js. Each one has one job, and this course visits them all.

    A wooden cabinet, in CSS

    A thick brown border is the wood. box-shadow takes a comma-separated list, and each shadow here does a different job: an inset one draws a dark line just inside the border, a shadow with no blur and a 3px spread draws a dark line just outside it, and the last one is the hard black drop shadow every arcade panel has. Three outlines and no extra elements.

    Buttons only for touch screens

    On a computer you boost with the space bar and use a power-up with B. A phone has neither, so the page has two real buttons, hidden by default. @media (pointer: coarse) asks "is the main pointer something blunt, like a finger?" Only then do the buttons appear. This is better than checking the screen width, because a small laptop window still has a keyboard, and a big tablet still doesn't.

    Two editions, one page. The controls text contains spans like <span data-only="full">A question comes every 30 seconds...</span> and <span data-only="free">...</span>. The build script for your free arcade keeps only the free text, so the same page serves the classroom arcade and the no-maths copy.

    QUIZ

    The canvas is shown 480 pixels wide on a phone. How wide does the game think it is?

    • 480 pixels
    • 960 pixels, from its width attribute
    • It depends on the CSS

    The attributes set the drawing surface. CSS only changes how big that surface looks, so the game's maths never has to change.

    When are the BOOST and POWER buttons shown?

    • When the window is narrower than 600px.
    • When the main pointer is coarse, like a finger on a touch screen.
    • Always, but only clickable on phones.

    @media (pointer: coarse) tests the kind of pointer, not the size of the screen.

    Why is the canvas's aria-label so long and descriptive?

    • The pixel font needs it.
    • Everything inside a canvas is just pixels, so the label is all a screen reader can describe.
    • It's shown as a tooltip during play.

    Buttons and text describe themselves. A painted picture doesn't, so the label has to.

    Course 5 · Lesson 2

    The Game Loop

    Tic-tac-toe only did something when you clicked. An action game never stops: the serpent keeps sliding whether you press anything or not. That takes a game loop, a function that runs once per frame and does two things every time: update the state a little, then draw it.

    All the state in one object

    Tic-tac-toe kept its state in separate variables. Jörmungandr has far more of it, so it lives in one object called game. That one object can then be handed to other files: play.js changes it, render.js draws it. Other fields (snake, items, thor) are added when a realm is set up.

    Starting the game

    runGame lives in js/game-shell.js and is shared by every canvas game in the arcade. Each game hands it an object of settings and functions, and it does the boring parts: check the session, load everything, then run the loop. Notice canvas, on its own: that's shorthand for canvas: canvas.

    Loading first

    Promise.all takes a list of promises and waits for all of them: the images, the question bank and the pixel font. Its result is a list of their results in the same order, which is why ready can pick out the art with ([loaded]) =>, destructuring the first item. If any of them fails, the whole thing fails, and the error lands in #load-error. The font is loaded on purpose: text drawn on a canvas before the font arrives would come out in a plain fallback font.

    The loop itself

    • requestAnimationFrame(frame) asks the browser to call frame just before it next paints the screen, usually 60 times a second. frame asks again at the end, so it keeps going for ever. The browser also pauses it in a hidden tab, which saves battery.
    • The browser passes now, a time in milliseconds. now - last is how long the last frame took. Divided by 1000 it becomes seconds, and that's dt ("delta time"), the number every update works with.
    • Math.min(..., 0.05) caps dt at a twentieth of a second. Come back to a tab after a minute and the first dt would be 60 seconds: without the cap, everything would leap a minute ahead in one frame. Math.max(..., 0) stops it ever going negative.
    • endFrame?.() uses optional chaining: call it only if the game supplied one. Jörmungandr doesn't, so nothing happens.
    Why seconds, not frames? Screens refresh at 60, 120 or 144 times a second. If the game moved "one bit per frame", it would run twice as fast on a 120Hz screen. Moving "this much per second, times dt" makes it the same speed on every screen.

    Counting a run when you leave

    If a player switches tab or closes the laptop mid-game, the score so far still goes to the leaderboard. run.score is a function, not a number, so it reads the score at the moment the tab is hidden rather than the 0 it was at the start.

    QUIZ

    A frame took 16 milliseconds. What dt does update get?

    • 16
    • 0.016
    • 0.05

    Milliseconds divided by 1000 gives seconds. It's under the 0.05 cap, so it's left alone.

    Why is dt capped at 0.05?

    • To make the game run at 20 frames a second.
    • So a long pause (a background tab, say) can't make everything jump far ahead in one frame.
    • Because requestAnimationFrame can't go faster.

    The loop still runs every frame. The cap only matters when a frame is unusually long.

    Why does run pass score: () => game.score instead of score: game.score?

    • Arrow functions are faster.
    • game.score would be copied once, as 0. The function reads the score whenever it's called.
    • recordRun only accepts functions.

    A number is copied when it's passed. A function can look up the current value later.

    Course 5 · Lesson 3

    A Board Made of Cells

    The serpent glides smoothly on screen, but underneath, the game is as blocky as tic-tac-toe. The board is a grid of cells, and the serpent, the food and Thor each sit in exactly one cell. All of that lives in board.js:

    22 columns of 40 pixel cells is 880 pixels, which leaves 40 pixels either side of the 960 pixel canvas: that's boardX. 11 rows is 440 pixels tall, starting 56 pixels down to leave room for the score bar. Every other number in the game is worked out from these, so the board could be resized by changing them.

    Cells and pixels

    The game logic talks in cells: "the head is at column 7, row 5". The drawing code needs pixels. Two small functions translate:

    Start at the board's edge, move across x whole cells, then half a cell more to reach the middle. Column 0's centre is 40 + 0 + 20 = 60; column 7's is 40 + 280 + 20 = 340.

    Is it on the board?

    Columns run from 0 to 21, so x < cols (strictly less) is the right test. This is how the game spots the serpent hitting a wall: the cell it's about to move into isn't inside.

    How far apart?

    The serpent can't move diagonally, so the useful distance isn't a straight line. It's the number of steps across plus the number of steps down, called the Manhattan distance after the grid of streets in New York. Math.abs drops the minus sign, so it doesn't matter which way round the two cells are. Thor uses this to decide how scared to be, and new food uses it to appear a few steps away from the serpent's nose.

    Nine realms, round and round

    Levels count from 1 and never stop, but there are only nine realms. level - 1 turns "level 1" into index 0, and % realms.length (the remainder after dividing by 9) wraps round: level 10 gives 9 % 9 = 0, back to Midgard. This "subtract one, take the remainder" pattern is how to cycle through any list with a counter that starts at 1.

    QUIZ

    What is centreY(2), with boardY = 56 and cell = 40?

    • 80
    • 156
    • 136

    56 + 2 × 40 + 20 = 156.

    What is the Manhattan distance from { x: 2, y: 5 } to { x: 6, y: 2 }?

    • 5
    • 7
    • 1

    4 across plus 3 up. (The straight-line distance would be 5, but a serpent can't cut corners.)

    Which realm is level 12?

    • The twelfth realm.
    • The third one, Alfheim: (12 - 1) % 9 is 2.
    • None. The game would crash.

    Index 2 is the third item in the list. After Asgard, the journey starts again.

    Course 5 · Lesson 4

    The Serpent Is a List

    Here is the whole trick of every snake game: the snake is just a list of cells, head first. Moving it doesn't mean moving every piece. You add a new head at the front and remove the tail from the back. Everything in between stays exactly where it is, and yet the whole snake appears to slide forward.

    • A direction is a little vector: how far to move in x and in y for one step. Up is y: -1 because canvas rows count downwards from the top.
    • ({ ...c, belly: -1 }) spreads a start cell into a new object and adds a belly field. It makes copies, so moving the snake can never change startCells itself. (The belly says which side of the body the brown belly stripe is on, for drawing.) The extra brackets round the { } tell JavaScript it's an object, not the body of the arrow function.
    • grow counts how many steps the tail should stay put. More on that below.

    Taking a step

    The step is split in two on purpose. takeTurn only works out the next cell: the head plus the direction. The game then checks that cell (is it a wall? the snake's own body?) and only calls advance if it's safe.

    unshift puts the new head at the front of the array, and pop takes the last item (the tail) off the end. Watch the start snake heading right:

    Growing is just not shrinking

    Eating an apple adds 1 to snake.grow. On the next step the head is added as usual, but the pop is skipped, so the snake is one cell longer. A golden egg adds 2, so the tail waits for two steps. Nothing has to be inserted into the middle of the body.

    Is the body here?

    A plain loop over the cells. The interesting part is tailMoves. When the head is about to step, the tail is about to leave its cell in the very same step, so chasing your own tail round a tight loop is allowed. But if the snake is growing, the tail won't move, and running into it is a crash. Get that wrong and the game either kills you unfairly or lets you pass through yourself.

    QUIZ

    The snake's head is at (3, 4) heading up. What does takeTurn return (with no turns queued)?

    • { x: 3, y: 5 }
    • { x: 3, y: 3 }
    • { x: 2, y: 4 }

    Up is { x: 0, y: -1 }, and rows count down from the top.

    A 4-cell snake with grow at 2 takes three steps. How long is it now?

    • 4
    • 6
    • 7

    The first two steps skip the pop. The third step adds a head and pops a tail, so the length stays at 6.

    Why does bodyAt sometimes leave the tail cell out?

    • The tail is too thin to crash into.
    • On a normal step the tail moves away at the same time, so the head can safely follow into it.
    • To make the game easier on early levels.

    Only when grow is 0, though. A growing snake's tail stays put, so it still counts.

    Course 5 · Lesson 5

    Steering the Serpent

    Turning, with rules

    A key press doesn't change the direction at once. It joins a short queue of turns, and takeTurn uses one per step. Why? The snake steps about four times a second. Press up then left quickly, inside one step, and without a queue the left would simply replace the up, and the snake would turn the wrong way, often straight into a wall.

    • snake.queue.at(-1) is the last item in the array (negative numbers count from the end). If the queue is empty, it's undefined, and ?? falls back to the current direction. Each new turn is compared with whatever the snake will be doing just before it.
    • The same direction again is ignored. Holding the key down would otherwise fill the queue with copies.
    • The exact opposite is ignored: a direction is a reverse if both its parts are the negatives of the other's. Heading right (x: 1), pressing left (x: -1) would drive the head straight back into its own neck.
    • At most two turns wait. Mash the keys and you won't build up a long list of moves that play out after you've stopped.

    Keys to directions

    A lookup object instead of a long if chain: adding another key is one more line. gameKeys spreads the steering keys into a list with the other keys the game uses.

    Listening

    1. A question is open? Then the keys belong to the answer box, not the game.
    2. event.key is "ArrowUp", "w", or "W" with Caps Lock on. toLowerCase() makes them all match the lookup's keys.
    3. Not a game key? Leave it alone, so shortcuts like Ctrl + R still work.
    4. preventDefault() stops the browser's own reaction. Without it, the arrow keys and space bar would scroll the page while you play.
    5. Space is held to boost, so keydown turns boosting on, keyup turns it off. If the window loses focus while space is down, the keyup never arrives, so blur turns it off too.
    6. event.repeat is true for the automatic repeats when a key is held. They still count for the boost, but they mustn't steer again and again.

    input.js doesn't know about snakes. It calls handlers.onSteer("up"), and game.js decides what that means:

    On the game-over screen, left and right pick a button. During play, the name becomes a direction vector for turn.

    Swipes

    On a touch screen, input.js watches pointer events on the canvas. Every 24 pixels dragged counts as a swipe, and the direction is whichever way the finger moved further:

    It calls the very same onSteer, so the game can't tell a swipe from a key press.

    QUIZ

    The snake is heading right with an empty queue. You press up, then right, very quickly. What's in the queue?

    • Nothing. Right is the current direction.
    • Up, then right.
    • Just up.

    Right is compared with the last queued turn (up), not the current direction. After going up, turning right is a real turn.

    Why does the keydown handler call event.preventDefault()?

    • To stop the key reaching the game.
    • So the arrow keys and space don't scroll the page.
    • To make the key repeat faster.

    It's only called for game keys, so every other key keeps its normal job.

    You hold the up arrow down. How many times does the snake try to turn?

    • Many times, once for every repeat.
    • Once. Repeats have event.repeat set and return before steering.
    • Never, until you let go.

    And even if they did get through, turn ignores the direction already queued.

    Course 5 · Lesson 6

    Moving to a Beat

    The game loop runs 60 times a second, but the serpent only moves about four times a second, one whole cell at a time. So the loop needs a way to say "not yet... not yet... now step". That's the job of a step clock.

    How long is a step?

    Level 1 is 0.26 seconds a step. Each level takes off 0.01, but Math.max(0.14, ...) sets a floor, so it never goes faster than 0.14 however high you climb. Boosting (or the star power-up) multiplies the step by 0.55, which makes the serpent nearly twice as fast.

    The step clock

    Every frame adds dt to stepClock. Once it holds a whole step's worth of time, the snake moves and that step's time is subtracted. Why subtract instead of resetting to 0? Say a step is 0.26 seconds and the clock reaches 0.27. Resetting would throw away the spare 0.01, and over many steps the serpent would drift slow. Keeping it means the beat stays steady.

    • The loop runs at most twice per frame. If a frame was long, the snake catches up by a step, but it never teleports several cells.
    • If the step killed the snake or opened a question, the phase is no longer "playing", so it stops at once.
    • Math.min(game.stepClock, step) throws away anything more than one step of spare time, so a slow moment can't store up a burst of extra moves.

    The boost meter

    game.boost runs from 0 (empty) to 1 (full). Draining takes away dt / 2.5 each frame, so a full meter lasts 2.5 seconds of holding space. When you let go it refills at dt / 6: six seconds from empty to full. Math.max(0, Math.min(1, ...)) clamps the value between 0 and 1, a pattern you'll see everywhere in games. The shield and the star's speed-up count down the same way, stopping at 0.

    QUIZ

    On level 20, how long is a step without boosting?

    • 0.07 seconds
    • 0.14 seconds
    • 0.26 seconds

    0.26 - 19 × 0.01 is 0.07, but Math.max(0.14, 0.07) is 0.14.

    A step is 0.25s. stepClock is 0.2 and the next frame's dt is 0.1. What happens?

    • No step. The clock is 0.3.
    • One step, and the clock is left at about 0.05.
    • One step, and the clock goes back to 0.

    0.3 is at least 0.25, so the snake steps and 0.25 is subtracted. The spare 0.05 counts towards the next step.

    What does Math.max(0, Math.min(1, value)) do?

    • Rounds the value to 0 or 1.
    • Keeps the value between 0 and 1.
    • Picks whichever of 0 and 1 is nearer.

    The min stops it going over 1, and the max stops it going under 0.

    Course 5 · Lesson 7

    Eating, Growing and Crashing

    One step, checked

    This is where the pieces from earlier lessons meet. Work out the next cell; if it's off the board or on the body (with tailMoves set to true), that's a crash. A shield turns the crash into a swerve; otherwise the game is told the snake died. Only a safe cell is moved into and then eaten from.

    hooks is an object of functions passed in from game.js: die, toast, sound and so on. play.js calls hooks.die() without knowing what dying involves (a sound, a flashing snake, losing a life). That keeps the rules separate from the presentation.

    Eating

    Each food is a row of data: how many points, how much to grow. foods[item.kind] looks up the row by the item's name, so adding a new food is one more line, not a new if. With the star power-up running, points are doubled. Growing is just adding to grow, which advance uses on the following steps.

    Food that comes and goes

    A boar turns up about every 24 seconds, give or take 6. Math.random() * 2 - 1 is a random number from -1 to 1, so the timer lands anywhere from 18 to 30. A little randomness stops the game feeling like clockwork.

    • Every item ages by dt, and filter keeps only the ones younger than their life. Expired items simply aren't copied into the new list.
    • An apple's life is Infinity, so age < life is always true and it never expires. There's always one waiting: if none is on the board, a new one is placed.
    • Each kind has a countdown. When it reaches 0 it's rolled again and a new item appears.

    Finding an empty cell

    Picking random cells until one is free is quick and fair while the board is mostly empty. But late in a game the serpent can fill most of the board, and random guesses might miss the last few gaps for a long time. So after 200 tries it gives up guessing and scans every cell in order. If even that finds nothing, it returns null, and the caller places nothing. Two strategies, the fast one first, the sure one as a fallback.

    isFree is a function passed in. board.js doesn't know about snakes or Thor; the caller decides what "free" means. Food is placed at least 3 steps from the head, "so it has to go and get it".

    The shield's swerve. sideTurns works out left and right of the current heading with a neat trick: for a direction { x, y }, the two turns are { x: -y, y: x } and { x: y, y: -x }. Swapping the parts and flipping one sign rotates a vector by a quarter turn. The shield picks whichever side isn't deadly.

    QUIZ

    The star power-up is running and the serpent eats a rune. How many points?

    • 50
    • 100
    • 300

    A rune is 50, and speedFor > 0 doubles it.

    What range can rollTimer("rune") return?

    • 0 to 11
    • 11 to 15
    • 7 to 15

    every is 11 and spread is 4, so 11 - 4 to 11 + 4.

    Why does freeCell scan every cell after 200 random tries?

    • Scanning is faster than guessing.
    • On a crowded board, guesses could keep missing the few free cells. The scan is sure to find one if any exist.
    • To place items in the top-left corner.

    Random first keeps placements spread out. The scan is the safety net.

    Course 5 · Lesson 8

    Thor Runs Away

    Thor is the reason to keep moving: catching him is the only way out of a realm. He doesn't attack. He just runs, and he's written to be good at it but not perfect, so a careful player can corner him.

    Turning up

    He arrives 16 to 30 seconds into a realm, a little later in each realm up to Asgard. He's placed with the same freeCell as the food, but at least 9 steps from the serpent's head, so you never get a free catch.

    Choosing where to run

    This is a simple kind of game AI: give every possible move a score, then take the highest. Thor has at most four moves (up, down, left, right), skipping any that aren't free.

    • away: the Manhattan distance from the serpent's head after the move. Further is better.
    • room: how many free cells are next to the new cell. A move into a dead end scores low, so he avoids corners.
    • When the serpent is within 7 steps, he's panicking, and distance counts three times over. Otherwise he doesn't care where you are and wanders, mostly at random.
    • Math.random() * 2.5 is a dash of chance. Without it he'd always pick the mathematically best move and be very hard to catch.

    Starting bestScore at -Infinity means the first free move always beats it. If no move is free, best stays null and he stays put.

    Compare this with tic-tac-toe's minimax. Minimax looked at every future of the game; Thor only looks one step ahead, with a rough "how good does this look" score. That's called a heuristic. It's nowhere near perfect, but it's fast, and in a real-time game, "pretty good, instantly" is what you want.

    Smooth movement on a grid

    Thor's real position is always a whole cell. But moveClock climbs from 0 to 1 between his steps, and the drawing code places him that fraction of the way from his last cell to his new one. This is linear interpolation, or "lerp": from + (to - from) * t. At t = 0 you get from, at t = 1 you get to, and in between a smooth slide. The rules stay simple and the picture stays smooth.

    The lightning bolt

    The bolt power-up sets thor.stunned = 6. While that's above 0, updateThor counts it down and returns early, before any of the running code: six seconds to reach him. If he isn't on the board yet, the bolt summons him with game.thor ??= spawnThor(...). ??= assigns only if the left side is null or undefined.

    QUIZ

    Thor is 3 steps from the serpent. Which matters most to his choice?

    • Pure chance.
    • Getting further from the head: he's panicking, so distance counts three times.
    • Staying near the middle of the board.

    3 is within the panic range of 7, so the score is away * 3 + room * 1.5 + a little chance.

    He's moving from column 4 to column 5 and moveClock is 0.25. Where is he drawn?

    • Column 4
    • Column 4.25
    • Column 5

    4 + (5 - 4) × 0.25 = 4.25: a quarter of the way there.

    Why does Thor's score include some Math.random()?

    • To make him faster.
    • So he isn't perfect and can be cornered.
    • Because two moves can't have the same score.

    A perfect runner on an open board would be no fun to chase.

    Course 5 · Lesson 9

    Drawing a Frame

    Every frame, the canvas is painted from scratch, back to front, like a painter laying down a background first and the details last. Whatever is drawn later covers what was drawn before.

    Background, board, items, Thor, serpent, effects (floating points, lightning), and the score bar on top. ctx is the canvas's 2D drawing context, the object with all the drawing methods, from canvas.getContext("2d").

    Flashing with Math.floor

    A dying serpent flickers: Math.floor(game.phaseTime * 10) % 2 === 0. phaseTime * 10 counts tenths of a second, the floor makes it a whole number, and % 2 is 0 on even tenths and 1 on odd ones. So the serpent is hidden for a tenth, shown for a tenth, five times a second. Items that are about to vanish blink the same way, and Thor blinks just before he leaves.

    Drawing the board once

    The board has 242 cells, gold runes, glowing cracks and a circle of runes. Drawing all that 60 times a second would be wasteful when it never changes. So each realm's board is drawn once onto a canvas that's never put on the page, kept in a Map, and then every frame copies the finished picture with a single drawImage. This is caching.

    The runes and cracks are placed "at random", but Midgard should look the same every visit. seeded returns a function that keeps its own s in a closure, and each call multiplies it and takes a remainder. The numbers look random, but the same seed always gives the same sequence. That's a pseudo-random number generator. Each realm gets its own seed, so each has its own pattern.

    Turning the head

    The head is one picture, facing left. To point it any way, the code moves the canvas instead of the picture. translate moves the origin (0, 0) to the head's centre, rotate turns the whole canvas round that point, and scale(-1, 1) flips it like a mirror. Then the picture is drawn at (0, 0), and comes out moved, turned and flipped. Math.atan2(dir.y, dir.x) turns a direction vector into an angle. save and restore put the canvas back afterwards, so nothing drawn later is turned too.

    QUIZ

    Why is the serpent drawn after the items?

    • The serpent's code is in a later file.
    • Things drawn later appear on top, so the serpent covers anything it slides over.
    • Items load more slowly.

    The canvas has no layers. Order of drawing is the only thing that decides what's in front.

    Why is each realm's board drawn onto its own hidden canvas?

    • So it can be printed.
    • It never changes, so drawing it once and copying it each frame is much cheaper.
    • Hidden canvases draw in colour.

    One drawImage replaces hundreds of drawing calls per frame.

    What does seeded(1234) give you?

    • The number 1234.
    • A truly random number.
    • A function that returns the same "random-looking" sequence every time it's made with that seed.

    That's why Midgard's runes are always in the same places.

    Course 5 · Lesson 10

    The Serpent's Body

    The serpent's body isn't a picture at all. It's procedurally drawn: code builds it from the list of cells every frame. A thick tube with blocky scales and a belly stripe, rounding every corner and tapering to a curled tail. body.js is the most mathematical file in the game, so take it slowly.

    A smooth line through the cells

    Joining cell centres with straight lines would give sharp right-angle corners. Instead, each cell's piece of body runs from the midpoint with the cell before to the midpoint with the cell after, curving through the cell's centre on the way. quad is a quadratic Bézier curve: it starts at a, ends at b, and is pulled towards the control point c without quite touching it. As t goes from 0 to 1, the point slides along the curve. On a straight run, the curve is a straight line; on a corner, it's a smooth bend.

    For every cell, 9 points are taken along its curve (stepsPerCell). Each point also records along (how many cells from the head it is) and w (how wide the body should be there). The head and tail cells have no neighbour on one side, so they use their own centre instead of a midpoint. addTangents then works out which way the line is heading at every point, so scales can be laid across it.

    Thick in the middle, thin at the ends

    The body is narrow just behind the head and flares out to full width. f is clamped to run from 0 to 1 across the neck. f * f * (3 - 2 * f) is a classic called smoothstep: it also goes from 0 to 1, but starts and ends gently, so the neck swells like a real one rather than as a cone. widthAt does the same kind of thing at the other end, narrowing the last few cells to a thin tail.

    Chunky pixels on purpose

    The concept art is pixel art, but a curve drawn straight onto a 960 pixel canvas would look smooth and modern. So the body is drawn onto a small hidden canvas, a third of the size (pixel is 3), then stretched three times bigger onto the game. With imageSmoothingEnabled = false, the browser doesn't blur the stretch, so every small pixel becomes a crisp 3 by 3 block.

    The tube itself is a trail of filled circles along the centreline: first slightly bigger dark ones for the outline, then the body colour on top. Overlapping circles of changing size make a tube that bends and tapers with no complicated shapes at all.

    Scales that stay put

    Each scale picks one of four shades of green to give the hide a mottled look. If the shade came from Math.random(), every scale would change colour every frame and the serpent would shimmer. Instead, the shade comes from a hash of the board cell the scale sits in. A big multiple of Math.sin jumps about wildly, and n - Math.floor(n) keeps just the part after the decimal point, a number from 0 to 1. Same cell in, same number out. As the serpent slides forward, its scales seem to stay where they are on the board, like a real snake's skin moving over the ground.

    QUIZ

    What is quad(a, c, b, 0)?

    • a, the start of the curve.
    • c, the control point.
    • b, the end of the curve.

    With t = 0, u = 1, so only the u * u * a part is left.

    Why is the body drawn small and then scaled up 3 times with smoothing off?

    • Small canvases are the only ones that support curves.
    • To get chunky, crisp pixels that match the pixel-art look.
    • To make it fit inside a cell.

    Each small pixel becomes a 3 by 3 block, with no blurring between them.

    Why do scales get their colour from hash(x, y, ...) instead of Math.random()?

    • hash is faster.
    • The same cell always gives the same colour, so scales don't flicker from frame to frame.
    • Math.random() can't give numbers between 0 and 1.

    The body is redrawn every frame, so the colours have to come out the same each time.

    Course 5 · Lesson 11

    Phases and the Question Gate

    The game is always in exactly one phase, a string in game.phase: "title", "intro" (the realm's name), "ready" (after losing a life), "playing", "dying", "question" or "over". Each phase decides what updates, what's drawn and what the keys do. This is a state machine, and it replaces dozens of separate true/false flags.

    phaseTime resets to 0 every time the phase changes, so any phase can ask "how long have I been going?". The realm intro shows for 2.2 seconds, "GET READY!" for 1.2, and then play starts by itself. Only in "playing" does updatePlay run, so the serpent freezes in every other phase without any extra code.

    A question every 30 seconds

    roundTime grows by dt only while playing, and the last line of updatePlay checks it: if (game.roundTime >= game.nextQuestion) hooks.question();. The deadline moves forward 30 seconds after each question, rather than the clock going back to 0. And because dying doesn't reset it, you can't dodge a question by crashing on purpose.

    Setting the phase to "question" first freezes the game (the loop keeps running and drawing, but nothing moves). Then the same questions.ask you met in tic-tac-toe waits until a question is answered right. The reward: 25 points and a full boost meter. inputDelay: 300 locks the answer box for 0.3 seconds, so a W or S you were still pressing to steer doesn't land in it.

    Clearing a realm

    Catching Thor sets game.thorCaught, and updatePlay calls hooks.cleared(), which is this function. One right answer, a bonus that grows with the level, and on to the next realm.

    Game over, or carry on

    • Losing the third life moves to "over", with two buttons drawn on the canvas: Restart (back to level 1) or Continue.
    • Continuing costs two right answers. askEach calls ask twice in a row, labelling them "Question 1 of 2" and "2 of 2", by calling the function it's given with each number.
    • You keep your realm but the score goes back to 0, because the leaderboard counts the best score from one set of three lives.
    • game.phaseTime < 1 ignores choices for the first second of the game-over screen. You were probably mashing keys as you crashed, and an Enter meant for the game shouldn't pick a button by accident.

    QUIZ

    You lose a life 20 seconds into a game. When is the next 30-second question?

    • 30 seconds after you start again.
    • After about 10 more seconds of play: the clock didn't reset.
    • Straight away.

    roundTime keeps counting across lives and realms. Only startMathClock resets it.

    Why does the serpent stop moving while a question is open?

    • The game loop is stopped.
    • The phase is "question", and updatePlay only runs in "playing".
    • await freezes the whole page.

    The loop keeps drawing the frozen scene behind the question.

    Why does chooseOver ignore input for the first second?

    • To give the high score time to save.
    • So keys pressed during play don't pick a game-over button by accident.
    • The buttons take a second to draw.

    It's the same idea as the question box's inputDelay.

    Course 5 · Lesson 12

    Scores and the Leaderboard

    A high score per player

    • Several students may share a computer, so the key includes the username: mathArcadeJormungandrHigh:ana. getSession()?.username uses optional chaining, so with no session it's undefined, and ?? "guest" fills in.
    • localStorage stores only strings. Number(...) turns "1250" back into 1250. A key that was never saved gives null, and Number(null) is 0. Something unreadable gives NaN, and NaN || 0 is 0.
    • Both are wrapped in try/catch. Some browsers (private modes, strict settings) throw an error when you touch localStorage. A high score isn't worth crashing the game over, so the error is caught and play goes on.
    • catch with no (error) is allowed when you don't need to look at the error.

    Drawing the score

    padStart(6, "0") adds zeros to the front until the string is 6 long: 1250 becomes "001250", the classic arcade look. The score bar is drawn on the canvas with label, which draws each piece of text twice: strokeText with a thick black line, then fillText in colour on top, giving the outlined lettering from the concept art.

    The class leaderboard

    Jörmungandr calls recordRun("jormungandr", game.score) at three moments: after each realm, at game over, and (through runGame) when the tab is hidden. Each signed-in student has one leaderboard document in Firestore, the arcade's online database.

    • !(points > 0) rather than points <= 0: if score were somehow NaN, NaN <= 0 is false and it would slip through. NaN > 0 is also false, so the ! version catches it.
    • update loads the student's saved entry and calls the arrow function with it. Returning null means "nothing new, don't save". Only a better score is written.
    • { [game]: points } is a computed key: the key is the value of game, so this makes { jormungandr: 1250 }. The same function serves several games.
    • Guests and the teacher have no document, so for them it quietly does nothing. And none of it ever throws: a dropped Wi-Fi connection can't break a game.
    The whole build, in one sentence: a canvas and a game loop paint the state sixty times a second, the board is a grid of cells, the serpent is a list that gains a head and loses a tail, a step clock sets the beat, data tables describe the foods and timers, a simple scoring heuristic makes Thor run, curves and caches make it look good, and phases decide when the questions come.

    QUIZ

    What does Number(localStorage.getItem(key)) || 0 give if nothing was ever saved?

    • null
    • NaN
    • 0

    getItem returns null, and Number(null) is 0. The || 0 also covers NaN.

    Why are the localStorage calls inside try/catch?

    • To make them faster.
    • Some browsers throw when storage is blocked, and the game should carry on anyway.
    • localStorage always throws the first time.

    Without the catch, a blocked browser would stop the game the first time it touched the high score.

    Your best is 900 and you finish a run on 600. What does recordRun save?

    • 600, the latest score.
    • 1500, the total.
    • Nothing. 600 isn't better, so the change function returns null.

    The leaderboard keeps your best single run.
