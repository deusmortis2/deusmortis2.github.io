COURSE 7: ASTRO STOMP

    Course 4 · Lesson 1

    A Tour of Astro Stomp

    Have a go first: play Astro Stomp on your site's free arcade. You fly an astronaut from Mercury out to Neptune. Each planet is a long side-scrolling level full of aliens, and a boss waits at the end beside your rocket. You jump, and press down in mid-air to smash whatever is underneath you.

    It's the biggest game in the arcade: about 6,500 lines spread over 39 files in js/astro/. This course won't go through them one by one. Instead it takes a guided tour of the main systems, reading the real code as it goes.

    The page

    The whole game happens on one 960 by 540 canvas. Everything you see in play (the planet, the aliens, the score, even the title screen) is drawn there by JavaScript.

    Already covered in Course 3. Deus Draconis taught the canvas basics, and Astro Stomp uses every one of them, so here they get just a sentence each:
    • Canvas and context: getContext("2d") gives the drawing tools. Astro Stomp asks for { alpha: false } because its picture always covers the whole canvas.
    • The game loop: the shared runGame() in game-shell.js calls update(dt) then draw() every requestAnimationFrame, with dt in seconds and capped at 0.05.
    • Input state: input.held("left") is "is it down now?" and input.pressed("jump") is "was it pressed this frame?".
    • Sprites, entities and collisions: images drawn with drawImage, game things as plain objects with x, y, w, h, and rectangle overlap tests.
    • Stage data and the question gate: levels written as data, and await questions.ask() that only resolves on a right answer.

    A map of the files

    • The boss of it all: game.js (phases, lives, score, questions) and world.js (one frame of play).
    • The ground: levels.js, stagesInner.js, stagesOuter.js and physics.js.
    • The astronaut: player.js, status.js and input.js.
    • The aliens: minions.js (the list), enemies.js and enemyKit.js (shared parts), and movesHot.js, movesWild.js, movesSky.js and movesIce.js (what each one does).
    • Bosses: bosses.js, bossKit.js, bossesInner.js and bossesOuter.js.
    • Things that fly or hurt: shots.js, strikes.js, hazards.js, patches.js and contacts.js.
    • Help and danger: powerups.js and oxygen.js.
    • Drawing: render.js, looks.js, hud.js and the *Art.js files, plus spriteSizes.js and machineSizes.js, which are written by art tools rather than by hand.

    One object holds the game

    Everything that lasts the whole trip (score, lives, power-ups, which planet) lives on game. Everything about the planet you're on right now (the astronaut, the aliens, the boss, every shot in the air) lives on game.round, which newRound() builds from scratch each time a planet starts. Throwing a planet away is then a single line: make a new round.

    Phases

    The game is always in exactly one phase: "title", "intro" (the planet's name card), "playing", "question", "clear" (the rocket taking off), "over" or "won". update only runs the code for the current one. phaseTime restarts at 0 on every change, which makes timed steps easy: the intro card stays up for 2 seconds, the rocket flies for 2.6. Notice the intro also waits for ready: the next planet's pictures must have loaded before you can play it.

    QUIZ

    Where does the list of aliens on the current planet live?

    • On game, next to the score.
    • On game.round, which is rebuilt for each planet.
    • In astro.html.

    Anything that belongs to one planet goes on the round, so starting a planet (or restarting it) is just building a new round.

    Why does setPhase reset phaseTime to 0?

    • To save memory.
    • So each phase can time itself, like "after 2 seconds of intro, start playing".
    • Because update would crash otherwise.

    phaseTime is "how long have we been in this phase?", which is exactly what timed steps need.

    When does the intro card give way to play?

    • As soon as the player presses a key.
    • After exactly 2 seconds, always.
    • After 2 seconds, and only once that planet's art has loaded.

    Both conditions must be true, so a slow connection just keeps the name card up a little longer.

    Course 4 · Lesson 2

    Planets Made of Data

    Course 3 showed stage data in Deus Draconis. Astro Stomp takes the idea further: each planet is one object that says where the floor, ledges, aliens and hazards go, and a builder turns it into a grid of tiles.

    Look at floor. It doesn't list tiles, it lists ranges: floor from column 0 to 22, then 26 to 44, and so on. The gaps between the ranges (23 to 25, 45 to 47...) are the pits. Mercury has lava: true, so those pits are lava. Each platform sits right over a pit, so there's always a way across. Writing ranges instead of every tile keeps a planet over 130 columns long to about twenty lines.

    Planets are spread over two files (inner and outer) only to keep each file short. levels.js joins them into one list:

    From data to a grid

    • The grid is an array of 12 rows, each an array of one-letter strings. grid[row][col] is one tile. Every tile starts as air, ".".
    • fill quietly ignores anything off the grid, so a typo in the stage data can't crash the builder.
    • The builder adds one extra floor range itself: the last 6 columns before the boss arena and the arena floor. Every planet needs that, so no stage has to remember it.
    • Lava is put only where row 11 is still air, which means only in pits.
    • strip(ch, offset) is a function that returns a function. strip("=") makes a painter for ledges, which forEach then calls with each [row, from, to]. Arena ledges use an offset because they're counted from the arena's left edge.
    • stage.spikes ?? []: most planets have no spikes, so a missing list counts as empty.

    Asking about a tile

    Everything else reads the level through tileAt, and it has a clever answer for places off the map. Past the left or right end it says "#", an invisible wall, so nothing can walk off the ends. Above the top or below the bottom it says ".", so you can jump above the screen and fall out of the bottom of a pit.

    The boss arena gate works the same way: setGate(level, true) writes a column of "#" into the grid just left of the arena, and from then on the physics treats it like any other wall.

    QUIZ

    Mercury's floor is [[0, 22], [26, 44], ...]. What is at column 24?

    • Solid floor.
    • A pit, and since Mercury has lava, a lava pool in row 11.
    • A one-way ledge.

    Columns 23 to 25 are outside every floor range. Lava fills row 11 wherever it is still air.

    What does tileAt(level, -1, 5) return?

    • ".", because it's off the map.
    • "#", so the left edge acts like a wall.
    • undefined.

    Off the left or right side always counts as solid, so nothing can leave the level sideways.

    What is strip("=")?

    • A string of equals signs.
    • A function that paints "=" along one [row, from, to] entry.
    • The number of platforms.

    strip returns a new function each time it's called, set up for one tile letter and offset. That's why it can be passed straight to forEach.

    Course 4 · Lesson 3

    Tile Collision Without Tunnelling

    Every body in the game (the astronaut, a walking alien, a dropped power-up) is a box with x, y, w, h and a velocity vx, vy in pixels per second. physics.js moves those boxes through the tile grid and stops them at walls and floors.

    Turning a pixel position into a tile is a division: Math.floor(x / tile). With 45-pixel tiles, x = 100 is in column 2 (it covers 90 to 134).

    Sideways first

    1. Move first, then check.
    2. Find the leading edge: the right side when moving right, the left side when moving left.
    3. Check every tile that edge touches, from the row of the head to the row of the feet.
    4. If one is solid, snap the body back so it's touching the wall but not inside it, and stop it. hitWall records which way it bumped (aliens use it to turn round).

    Why - 0.01? An astronaut standing on the floor has their feet at exactly 450, the top edge of row 10 (10 × 45). Without the tiny nudge, the check would count row 10 as one the body covers, and every floor tile beside their feet would look like a wall.

    Then up and down, with one-way ledges

    A "=" ledge is the classic platformer trick: you can jump up through it from below and still land on it from above. The rule is one line. A ledge only catches you if your feet were above its top edge before this move (oldBottom). Rising through it, your feet started below, so it lets you pass. Moving up only checks isSolid, so ledges never bump your head.

    Landing is also where onGround becomes true. The player code reads that flag to decide whether a jump is allowed.

    Small steps, so nothing tunnels

    A smash drops the astronaut at 1,900 pixels per second. In a 0.05-second frame that's 95 pixels, more than two whole tiles. If the body jumped 95 pixels in one go, it could start above a ledge and finish below it without ever being in it, and fall straight through. That bug is called tunnelling.

    The fix: split the move into steps of at most maxStep (18 pixels, less than half a tile). 95 pixels becomes 6 steps of about 16, and one of them is sure to land in the ledge's row. Once the body lands, it finishes its sideways movement in one go and stops stepping. Gravity is added first, and fall can be swapped: the astronaut passes a lower gravity, and a smash passes 0.

    Recap from Course 3: touching other bodies (aliens, shots, power-ups) doesn't use tiles at all. It's the same rectangle overlap test you met there, overlaps(a, b) in physics.js.

    QUIZ

    The astronaut jumps up from underneath a "=" ledge. What happens?

    • They bump their head and fall back.
    • They pass up through it, and can land on top of it on the way down.
    • They get stuck inside it.

    Moving up only stops at solid "#" tiles, and a ledge only catches feet that were already above it.

    A body falls 80 pixels in one frame. How many steps does moveBody split that into?

    • 1
    • 5
    • 80

    Math.ceil(80 / 18) is 5, so each step moves 16 pixels, never enough to skip over a tile.

    Which tile does moveX check when the body moves left?

    • The column at the body's right edge.
    • The column at the body's left edge, for every row it covers.
    • Only the row of its feet.

    The leading edge is the one that could run into something. Every row from head to feet is checked so tall bodies hit low walls too.

    Course 4 · Lesson 4

    The Astronaut: Run, Jump, Smash

    Good platformer controls are mostly small tricks you never notice. player.js has several, and they start with the numbers:

    The astronaut falls with about half the world's gravity (1,150 instead of 2,200), so jumps feel like space. Tuning the feel of the game is changing these numbers, not the code.

    Speeding up and slowing down

    • dir is -1, 0 or 1. Holding both arrows cancels out to 0.
    • The astronaut doesn't jump straight to full speed. approach moves vx towards the target speed by at most accel * dt each frame, and never overshoots. Letting go means the target is 0, so they slow to a stop the same way.
    • Every effect is a small change to one number: a mind ring flips dir, goo cuts the top speed, ice cuts the acceleration to 18% (so you slide), and steering in mid-air is a bit weaker than on the ground.

    Forgiving jumps

    And from the timers, run every frame:

    Three tricks are packed in here:

    • Coyote time. Like a cartoon coyote running off a cliff, you can still jump for 0.1 seconds after leaving a ledge. coyote is topped up while you stand and runs down once you don't. Without it, pressing jump a hair too late at the edge would do nothing, and it would feel like the game ignored you.
    • Jump buffering. The opposite mistake: pressing jump just before you land. The press is remembered in buffer for 0.12 seconds, so if you touch down in that time, the jump happens anyway.
    • Variable jump height. If you let go of jump while still rising fast, your upward speed is cut to 260. Tap for a hop, hold for a full jump.

    The smash

    Pressing down in the air sets player.smash to an object. While it's there, updatePlayer skips normal steering and runs smashing instead: hang in the air for 0.08 seconds (a tiny pause that makes it feel heavy), then plunge straight down at 1,900 pixels per second with gravity switched off. Hitting the ground clears it and reports a "slam".

    updatePlayer returns a list of events like ["jump"] or ["slam"] rather than playing sounds itself. world.js turns them into sounds, dust and screen shake. The player file stays about movement only.

    QUIZ

    You run off a ledge and press jump 0.05 seconds later. What happens?

    • Nothing: you're in the air.
    • You jump, because coyote time hasn't run out yet.
    • You smash.

    coyote was 0.1 when you left the ground and is still above 0, so the jump is allowed.

    What does approach(250, 0, 100) return?

    • 0
    • 150
    • 350

    It moves 250 towards 0 by at most 100.

    Why does updatePlayer return events instead of calling play("jump") itself?

    • Sounds can't be played from modules.
    • It keeps movement separate from sound and effects, which are handled in one place in world.js.
    • Events are faster.

    The player code reports what happened. Something else decides how that looks and sounds.

    Course 4 · Lesson 5

    Stomp or Ouch?

    Every platformer has to answer one question many times a second: the hero is touching an enemy, so who gets hurt? In contacts.js the answer depends on how they touch.

    What counts as "on top"?

    Overlapping isn't enough: you also need to be coming down (vy > 0), and your feet must be only a little way into the alien, less than 40 pixels or half its height, whichever is smaller. If your feet are deep inside it, you ran into its side. The "half its height" part matters for small aliens like spiderlings, where 40 pixels would be most of the body.

    A stomp has rules too

    Read it as a list of rules, checked in order. The first one that matches wins:

    1. Spiky (a red-hot beetle): stomping hurts you.
    2. Guarded (a crab with its claws up): you bounce off with a clang.
    3. A smash, or a stunned alien: a high bounce and one point of damage.
    4. Anything else: a plain jump on its head just bounces you. This is Astro Stomp's twist: you have to smash to do damage, and the game tells you so the first time.

    The order matters. A spiky alien that is also guarded must hurt, so spiky is checked first. Early returns keep each rule on its own and stop the later ones running.

    The bounce and its grace period

    Right after a bounce you're still overlapping the alien, but now moving up, so next frame you're not "on top" any more. Without bounceGrace, that next frame would count as a side touch and hurt you for a perfectly good stomp.

    Getting hurt

    hurt lives in game.js and is passed into resolveContacts(game, hurt) as a callback. The contact code only decides that you were hurt and from where; the game decides what it costs. After a hit, hurtFor gives 1.4 seconds when nothing can hurt you again (the astronaut blinks), so one alien can't take three lives in three frames. Falling into a pit ignores the shield and the star, because they can't save you from a bottomless drop: you're put back on the last safe ground instead.

    QUIZ

    You fall onto a plain cinder crab without pressing down. What happens?

    • The crab is beaten.
    • You bounce off and the crab is unharmed.
    • You lose a life.

    Only a smash (or landing on a stunned alien) does damage. A plain stomp just bounces.

    You smash down onto a magma beetle while it's glowing red hot (spiky). What happens?

    • The smash beats it because smashes always win.
    • You get hurt: spiky is checked before smashing.
    • You clang off.

    The first matching rule wins, and the spiky rule comes first.

    What is bounceGrace for?

    • Making bounces higher.
    • Stopping the alien you just bounced off from hurting you while you still overlap it.
    • Counting how many times you've bounced.

    For 0.3 seconds after a bounce, side touches don't hurt.

    Course 4 · Lesson 6

    Aliens as Data

    There are 33 kinds of alien: four per planet plus the Brood Queen's spiderlings. They all share one body-making and updating system, and each kind is a single line of data in minions.js:

    • art names the picture, points the score and speed the walking pace.
    • faces says which way the artwork looks (1 right, -1 left, 0 straight at you), so the renderer knows when to flip it.
    • move is a function stored as data. Each kind points at its behaviour, like scuttle or molten. That's next lesson.
    • ...flier spreads shared settings into every flying alien, so "fliers have a smaller hit box and ignore gravity" is written once.
    • Optional extras only appear where needed: onDeath (the slug splits in two), hp, scale, shell.

    A body sized from its picture

    spriteSizes.js is written by the art cutting tool, not by hand: it records each picture's size, like "mercury/crab": [76, 54]. The collision box is a share of that picture: 72% of its width and 88% of its height by default. Art is rarely a perfect rectangle (claws, antennae, empty corners), so a slightly smaller box feels fairer. Redraw a crab bigger, re-run the cutter, and its hit box follows with no code change.

    Making one

    • createEnemy takes a stage entry like ["cindercrab", 10] and destructures it, with row = 9 (standing on the floor) when it's left out.
    • Walkers are placed with their feet on the row; fliers hover with their middle there.
    • age and timer start a little random, so two crabs side by side don't move in perfect step.
    • def.setup?.(enemy, row): ?. calls setup only if this kind has one (the Mars crawler uses it to start hanging from the roof).

    Flags are rebuilt every frame

    clearFlags sets spiky, guarded, harmless, glow, tint and the rest back to "off" at the start of every frame. Then the move function switches on only what is true right now. A beetle is spiky because this frame's molten said so. Nobody has to remember to switch a flag off again, so a flag can never be left on by mistake. It's the same idea as Course 2's render() starting each square with className = "cell".

    QUIZ

    What is stored in a kind's move field?

    • A speed in pixels per second.
    • A function that runs that alien's behaviour each frame.
    • The name of a sound.

    Functions are values in JavaScript, so they can sit in a data table like any number or string.

    A crab picture is 76 by 54 pixels and uses the default box. How wide is its hit box?

    • 76
    • 55
    • 48

    76 × 0.72 = 54.72, rounded to 55.

    Why does updateEnemy call clearFlags before the move function?

    • To make the alien invisible for a frame.
    • So each frame starts with every flag off and the move function turns on only what's true now.
    • To reset the alien's health.

    Rebuilding flags from scratch means none can be accidentally left on.

    Course 4 · Lesson 7

    Move Sets: Little State Machines

    The four moves*.js files hold about 30 behaviours. Nearly all of them are state machines: the alien is in one named state at a time, a timer counts down, and when it runs out (or the player comes close) it switches to the next state.

    The cinder crab

    Three states, round and round:

    • patrol: walk back and forth. Once the cooldown is over and you're within 300 pixels on the same floor, turn to face you and go to...
    • windup: stand still for 0.35 seconds (the renderer shakes anything in "windup", which is your warning). Then...
    • rush: charge at triple speed for 1.1 seconds, then back to patrol with a cooldown.

    The wind-up is a design rule across the whole game: every attack tells you it's coming. That's what makes a hard game feel fair.

    Shared parts

    walk, windup, nearby and faceTowards come from enemyKit.js, a toolbox every behaviour uses:

    cooldown is how difficulty rises across the trip. Each planet has a pace: 1 on Mercury up to 1.45 on Neptune. Dividing the rest time by the pace means a crab that rests 1.2 seconds on Mercury rests about 0.83 on Neptune. One number per planet makes every alien a bit fiercer, without touching a single behaviour.

    A state table

    Here the state machine is written as data: steps maps each state to the next one and how long it lasts. hot, then vent, then cool, then hot again. The last three lines set this frame's flags from the state: hot and venting are spiky with an orange glow, cool is grey and safe to smash. The cool spell is not shortened by pace, so the beetle's opening stays fair even on later planets.

    The sky aliens share a general version of this, loop(enemy, round, steps) in movesSky.js, which takes a list like [["idle", 2.8], ["flap", 0.5], ["blow", 1.8]]. The gale wyvern uses exactly that, and during "blow" it calls shove(player, ...) to push you sideways.

    Telling the rest of the game

    emit(round, "steam", enemy) doesn't play a sound. It adds { type: "steam", x, y } to round.events, and playEvents in contacts.js looks the type up in a table of effects (steam: { colour: "#e8e8e8", sound: "whoosh" }). It's the same "report, don't do" pattern the player uses.

    QUIZ

    Why does the cinder crab spend 0.35 seconds in "windup" before rushing?

    • To let its animation load.
    • To warn the player (it shakes) so the charge can be dodged.
    • Because walk needs a pause.

    Every attack in the game is signalled first. Fair warning is a design rule.

    Neptune's pace is 1.45. About how long does cooldown(round, 2.9) come to there?

    • 4.2 seconds
    • 2.9 seconds
    • 2 seconds

    2.9 ÷ 1.45 = 2. A higher pace means shorter rests.

    A magma beetle is in "vent" and its timer runs out. What comes next?

    • "cool" for 2.2 seconds, with a puff of steam.
    • "hot" for 3 seconds.
    • It stays in "vent".

    steps.vent is ["cool", 2.2], and switching to cool emits steam.

    Course 4 · Lesson 8

    Bosses and the Open Moment

    Walking into the arena

    round.fight is a tiny state machine of its own: "before", "on", "won". One step into the arena shuts the gate (a column of wall tiles), creates the boss and moves the checkpoint to the arena door, so losing your lives to a boss lets you continue right outside its room.

    A boss is a table of attacks

    Bosses use the same state machine idea as aliens, written as an object of small functions, one per state. steps[boss.state]() looks up the function for the current state and calls it. Magmaw's fight goes:

    1. walk towards you, then pick the next attack.
    2. hurl: shake and glow while the timer runs (the warning), then throw a fan of lava rocks.
    3. slam: send shock waves along the floor both ways, which you have to jump. A big attack leaves it...
    4. tired: crouched and open. This is your moment to smash it.

    The helpers come from bossKit.js:

    boss.turn % list.length walks through the list and wraps round: hurl, slam, hurl, slam... A fixed order makes a boss learnable. Beating it is about spotting the pattern.

    Damage only when it's open

    In touchBoss (in contacts.js), a stomp or smash calls hurtBoss(boss, 1) only when boss.open is true; otherwise you just bounce off with the hint "WAIT TILL IT'S WORN OUT!". After a hit, grace stops the same smash counting twice in a row of frames. And at half health the boss turns angry: Magmaw walks faster, throws five rocks instead of three, rains rocks after a slam and rests for less time. A second phase, from one boolean.

    QUIZ

    With ["hurl", "slam"] and boss.turn at 5, which attack does nextAttack pick?

    • "hurl"
    • "slam"
    • undefined

    5 % 2 is 1, and list[1] is "slam".

    When can a smash take health off Magmaw?

    • Any time you land on its head.
    • While it's open, in the tired state after a slam.
    • Only while it's angry.

    The tired state sets open = true. At any other time a stomp just bounces.

    Magmaw has 5 hp. After which hit does it become angry?

    • The first.
    • The third, when it drops to 2 hp.
    • The last.

    Angry starts when hp <= max / 2, which is 2.5. After two hits it has 3, after three it has 2.

    Course 4 · Lesson 9

    Shots, Lobs and Warning Strikes

    One table for everything thrown

    Fireballs, shock waves, frost and mind waves are all the same kind of object. What makes them different is a handful of settings: gravity (does it fall?), runs (does it slide along the floor?), land (does it leave a burning or acid patch where it lands?), effect (does it freeze or confuse instead of hurting?) and life (how many seconds before it disappears anyway).

    Throwing so it lands on you

    A flame imp wants its fireball to land where you're standing, in 0.95 seconds. Sideways is easy: distance divided by time. Up and down is harder, because gravity bends the path. The physics formula for distance fallen is y = vy × t + ½ × g × t². Solving that for the starting speed gives vy = y / t - ½ × g × t, which is exactly the second line. Picking the time rather than the speed is the trick: a near target gets a gentle lob and a far one a faster throw, but both take the same time, so you always get the same amount of warning.

    Moving them all

    Moving and deleting happen in one filter: return true to keep a shot, false to drop it. A shot goes when it leaves the level, runs out of life, or is blocked (hit a wall, landed, or a floor runner ran out of floor). Blocked shots splash first, which may leave a fire patch or burst into shards. Note def.gravity ?? 0: shots with no gravity setting just fly straight.

    Strikes: warn, then hit

    Lightning bolts, ice spikes and breath beams hit a fixed spot. First they show a warning for warn seconds, then they're live for on seconds. Only a live strike can hurt (strikeLive checks fired). A "mark" is a strike that's only a warning circle: when it fires, its fire function drops something from the sky. That's how angry Magmaw's rainDown works: a red circle on the floor, then a lava rock falls right there.

    QUIZ

    What makes a shock wave slide along the floor instead of flying through the air?

    • It has a large gravity.
    • Its kind has runs: true.
    • Its life is short.

    Floor runners sit on the floor and are removed when the floor under their leading edge runs out.

    A lob covers 300 pixels sideways in 0.75 seconds. What is its vx?

    • 225
    • 400
    • 300

    300 ÷ 0.75 = 400 pixels per second. Gravity doesn't change sideways speed.

    A strike has warn: 0.9 and on: 0.5. When can it hurt you?

    • From the moment it appears.
    • From 0.9 seconds after it appears until 1.4 seconds.
    • Only at exactly 0.9 seconds.

    It warns first, fires at warn, stays live for on, then the filter removes it.

    Course 4 · Lesson 10

    Power-ups and the Drop Table

    Two tables. powerInfo says what each power-up looks like and how long it lasts (no seconds means it's used up some other way). dropTable says how likely each one is. The weights add up to 98, so oxygen turns up about 24 times in 98 and a heart only 4.

    Picking by weight

    Picture the weights laid end to end on a ruler 98 long: o2 takes 0 to 24, shield 24 to 39, and so on. roll is a random point on the ruler. Subtracting each weight in turn and stopping when it goes below 0 finds which piece the point landed in. [, weight] destructures each entry but skips the name, since only the weight matters there.

    bossDrops reuses pickKind on a filtered table. Removing the heart from the list is enough: the other weights still work, because pickKind adds up whatever it's given. And a beaten alien drops anything at all only 35% of the time.

    Timers that run down

    The player's powers are one object from newPowers(): { blaster: 0, boots: 0, quake: 0, shield: 0, speed: 0, star: 0 }. Each is "seconds left", and "is the blaster on?" is simply powers.blaster > 0. Picking one up sets its timer to the full amount (picking up a second one doesn't stack, it refills). tickPowers runs every frame and counts only the timed ones down, stopping at 0. The shield is the odd one out: it's a count of hits, and hurt() in game.js sets it back to 0 when it soaks one up, as you saw in Lesson 5.

    QUIZ

    With the drop table above, which power-up is picked when roll starts at 30?

    • o2
    • shield
    • blaster

    30 − 24 = 6, still not below 0. 6 − 15 = −9, below 0, so it stops on shield.

    You pick up speed boots with 4 seconds left on your current pair. How long do they last now?

    • 16 seconds
    • 12 seconds
    • 4 seconds

    apply sets the timer to info.seconds; it doesn't add to what's left.

    Why does tickPowers skip the shield?

    • It forgot to.
    • The shield has no seconds: it lasts until it blocks a hit, however long that takes.
    • The shield counts up instead.

    Only kinds with seconds in powerInfo are timers.

    Course 4 · Lesson 11

    One Frame, Start to Finish

    You've now seen every big system. world.js is where they meet. Here is everything that happens during one frame of play, in order:

    1. Move everything. The astronaut, then hazards, aliens, the boss, strikes and shots. Each updates itself.
    2. Turn events into effects. Everything that moved has added its events ("steam", "throw", "quake") to round.events; playEvents plays them all and empties the list.
    3. Then decide who touched what. resolveContacts runs once, after all the movement, so everything is checked in its final position for this frame.
    4. Then the bigger picture: the boss fight, the rocket, hints, and finally the camera.

    Dead aliens aren't removed straight away. dying counts up from 0 while the renderer squashes and fades them, and the filter drops them once they've been dying for 0.45 seconds.

    A smooth camera

    The camera is one number: how far the view has scrolled right. Ideally the astronaut sits 40% of the way across the screen, so you see more of what's ahead. In a boss fight the camera centres on the arena instead. It's clamped so it never shows past either end of the level. Then the last line moves the camera only part of the way to where it wants to be each frame (about 13% at 60 frames a second). That's called easing: it follows quickly when you're far off and gently when you're close, so the view glides instead of jerking.

    Drawing, in layers

    • "Pure output": the renderer only reads state. All the game rules live in the update code, so you could swap the art for coloured boxes and the game would play the same.
    • Painter's order: later drawings cover earlier ones, so the list runs from back (sky) to front (dust).
    • Screen shake is a random translate of everything between save and restore. The HUD is drawn after restore, so the score stays still while the world shakes.
    • Parallax: drawBackground scrolls the sky at 0.3 times the camera's speed, so it looks far away.

    Fast enough for a Chromebook

    A screen shows about 22 columns by 12 rows of tiles. Drawing 264 small pictures every frame adds up on a school laptop, so render.js paints the tiles that never move into chunks: canvases 16 tiles wide, made once and kept. Each frame then draws two or three big pictures instead. The cache key is a fingerprint of the chunk's tiles, so when the arena gate shuts (and the grid changes), that chunk is repainted.

    looks.js uses the same trick for effects: tintedCopy makes the grey "cooled beetle" version of a sprite once and keeps it in a Map, and glows are painted once per colour and stretched into place. Build it once, reuse it every frame.

    Here's the faces field from Lesson 6 at work. If the art looks right but the alien is walking left, scale(-1, 1) mirrors the drawing. One picture serves both directions, and aliens drawn facing you (faces: 0) are never flipped.

    QUIZ

    Why does resolveContacts run after everything has moved?

    • It's the slowest function.
    • So every touch is checked with everything in its final position for this frame.
    • Because the renderer needs it.

    Checking halfway through would test some things in old positions and some in new ones.

    The camera is at 100 and wants to be at 500. With dt of 0.05, where is it after one frame?

    • 500
    • 260
    • 120

    Math.min(1, 0.05 × 8) is 0.4, and 0.4 of the 400-pixel gap is 160. 100 + 160 = 260.

    Why is the HUD drawn after ctx.restore()?

    • So it's drawn behind the world.
    • So screen shake moves the world but not the score and meters.
    • Because the HUD uses a different canvas.

    restore undoes the shake's translate, so the HUD is drawn steady on top.

    Course 4 · Lesson 12

    Oxygen, Score and Game Over

    The oxygen meter

    Oxygen is what keeps you moving. A full meter (30) lasts 20 seconds, and drains five times faster inside a Venus miner's poison cloud. Read the rules straight from the code:

    • The boss fight pauses it. Once fight isn't "before", breathe returns at once. A boss is hard enough without a clock.
    • Empty means choking. At 0, choke counts down 2 seconds, then breathe returns true (lose a life) and starts another 2 seconds. You have time to reach a tank, but not long.
    • Only tanks and bubbles refill it. An O2 tank on the ground fills the meter and gives back a lost life (up to 3); an oxygen bubble power-up adds 12.

    breathe doesn't take the life itself. It returns true and lets game.js decide, which keeps the oxygen file small and easy to test. (You'll write one just like it in the next lab.)

    Where it's called

    Notice if (game.phase !== "playing") return; appears twice. updateWorld might hurt you and choke might take your last life, and either can switch the phase to "over". Checking again stops the rest of the function playing on after the game has ended.

    The question gate, Astro style

    You know questions.ask from Course 3. Astro Stomp's twist: while the phase is "question", updatePlaying doesn't run, so the world freezes and the oxygen clock and the planet timer stop. A right answer gives 100 points, clears every shot in the air and a 2.5-second shield, so you're never hit the instant play resumes. It does not give oxygen: answering questions can't replace finding tanks. input.clear() on both sides stops a key you were holding from leaking into the question box or back into the game.

    The launch bonus

    Reach the rocket and you get 3,000 points, less 12 for every second the planet took. Math.round(bonus / 10) * 10 rounds to the nearest ten (2,268 becomes 2,270), and Math.max makes sure even a very slow planet pays 150. clockText shows the time as "1:05": % 60 is the seconds left over after whole minutes, and padStart(2, "0") turns "5" into "05".

    Out of lives

    When the last life goes, the score is sent to the leaderboard first (recordRun), so it still counts. Then you choose. C calls retryPlanet: you keep your place (the last flag you touched, or the boss's door) but start again with 3 lives, no power-ups and a score of 0. R calls startMission(0), back to Mercury. Either way, a high score has to be earned in one go.

    Finally, the furthest planet you've reached is kept in localStorage under "astroStompReached", inside try/catch because private windows can refuse storage. That's what lets you press C on the title screen to carry on another day.

    The whole game, in one breath: planets are data built into a tile grid, small-step physics moves boxes through it, aliens and bosses are data tables pointing at little state machines, everything reports events instead of making noise itself, one function decides every touch, a renderer that only reads draws it all in layers, and game.js keeps score, lives, oxygen and questions on top.
